# 실지출 트래커

내가 한 번에 결제하고 친구들이 나중에 돈을 보내주면, 은행 앱은 결제를 지출로, 친구들 송금을 수입으로 따로 적어요.
이 앱은 그 송금을 원래 결제에 연결해서 **내가 실제로 쓴 돈**을 보여줘요.

- AI(Claude)가 지출을 카테고리(식비·편의점·술·유흥·구독료·교통비·쇼핑·생활·송금·기타·제외)로 분류
  - 친구 송금·페이 결제처럼 거래마다 용도가 다른 항목과 AI가 확신하지 못한 항목은 **거래 → 분류 확인**에 모여요
  - 이런 거래는 AI가 앞뒤 결제·시각·금액·친구 정산·내가 전에 고른 예시를 보고 하나씩 추측하고, 이유와 확신도를 같이 보여줘요
  - '제외'(환전·투자·저축)는 실지출에서 빠져요
- 친구 송금이 어느 결제(들)의 더치페이인지 AI가 연결을 제안 → 내가 확정
- 결제 취소(토스의 플러스 금액 체크카드결제)는 원래 결제에 자동 연결
- 이번 달 실지출, 카테고리별·이번 주 막대그래프, 예산 대비 현황
- 예산·지난 주와 비교해 줄일 수 있었던 곳을 짚어주는 주간 보고서 (지난 주 것은 자동으로 만들어요)

## 처음 시작하기 (팀원용)

필요한 것: Python 3.11 이상, [Anthropic API 키](https://console.anthropic.com) (각자 발급)

1. 저장소를 받아요.

   ```bash
   git clone <저장소 주소>
   cd spending-tracker
   ```

2. 패키지를 설치해요.

   ```bash
   pip install -r requirements.txt
   ```

3. `.env.example`을 복사해 `.env`를 만들고 `ANTHROPIC_API_KEY=` 뒤에 **자기** 키를 넣어요.

   ```bash
   copy .env.example .env
   ```

   키가 없어도 앱은 켜지지만, AI 분류·정산 제안·보고서는 꺼져요.

4. 서버를 켜요. Windows는 `start.bat`을 더블클릭해도 돼요.

   ```bash
   python -m uvicorn app.main:app --reload
   ```

5. 브라우저에서 http://127.0.0.1:8000 을 열고, 아래 **＋** 버튼으로 `samples/sample_toss.pdf`(비밀번호 `900101`)를 올려 보세요.
   연습용 가짜 거래내역이에요.

화면 디자인을 맡았다면 [DESIGN.md](DESIGN.md)부터 보세요. 서버나 API 키 없이 작업할 수 있어요.

## 공유하면 안 되는 것

- `.env` — API 키. 다른 사람이 가져가면 내 계정으로 요금이 나가요.
- `data/` — 내 실제 거래내역이 담긴 DB.
- 실제 거래내역서 PDF·엑셀.

`.gitignore`가 이것들을 막고 있어요. 커밋하기 전에 `git status`로 한 번 더 확인해 주세요.

## 사용법

1. 토스 앱에서 토스뱅크 통장 → 거래내역 → 거래내역서 발급으로 PDF를 받아요. 엑셀·CSV도 올릴 수 있어요.
2. 아래 **＋** 버튼으로 올려요. PDF에 비밀번호가 걸려 있으면 비밀번호 칸에 넣어요.
3. **정산**에서 AI가 연결한 송금을 확정하거나 거절해요. 확정한 금액만 실지출에서 빠져요.
4. **거래 → 분류 확인**에서 친구 송금·페이 결제의 용도를 골라요.
5. 홈 오른쪽 위 톱니바퀴에서 카테고리별 한 달 예산을 정해요.
6. 새 주가 시작된 뒤 앱을 열면 지난 주 보고서가 자동으로 만들어지고 홈에 카드가 떠요.
   다른 주의 보고서는 **보고서**에서 주를 고르고 만들 수 있어요.

PDF는 표를 먼저 읽고, 표가 안 잡히면 날짜로 시작하는 줄을 읽고, 그래도 안 되면 AI가 PDF 텍스트를 읽어 거래를 정리해요
(이때 PDF 텍스트가 Claude API로 전송돼요).

## 정산 규칙

- 정산 후보: 결제 2시간 전부터 결제 7일 후까지 들어온 입금 (친구가 미리 보내는 경우가 있어서).
  급여·이자·환불·캐시백 등은 제외하고, 이미 결제 취소된 결제와 송금·제외 카테고리 결제는 후보에서 빼요.
- 입금 하나가 여러 결제의 몫일 수 있어요(1차 식당 + 2차 카페). 이때는 결제 금액 비율대로 나눠 연결해요.
- 실지출 = 결제액 − 그 결제에 돌아온 정산 금액의 합 (0원 아래로는 내려가지 않음)
- 확인 대기 중인 정산은 실지출에 반영하지 않고 "확정하면 얼마"로 따로 보여줘요.
- 내 계좌끼리 오간 돈은 가져오지 않아요: 비상금, 환전, 거래내역서 **예금주**(내 이름)와 오간 돈.
  예금주 이름은 PDF에서 한 번 읽으면 기억해 두고, 이후 CSV를 올릴 때도 적용해요.

## 구조

| 경로 | 하는 일 |
|---|---|
| `app/parser.py`, `app/pdf_reader.py` | PDF·엑셀·CSV → 거래 목록 |
| `app/settle.py`, `app/stats.py` | 정산 후보 규칙, 실지출 집계 (AI 없음) |
| `app/agent/` | Claude 호출: 카테고리 분류, 거래별 추측, 들어온 돈 분류, 정산 매칭, PDF 추출, 주간 보고서, 콘솔 에이전트 |
| `app/categories.py` | 기본·사용자 카테고리 (이모지, 추가·삭제) |
| `agent_app/` | 콘솔 에이전트와 대화해 보는 최소 예제 |
| `app/service.py` | DB와 위 모듈을 엮는 앱 동작 |
| `app/main.py` | FastAPI 서버 |
| `static/` | 화면 (HTML·CSS·JS, 빌드 과정 없음) |
| `demo/` | 서버 없이 보는 공유용 데모 만들기 |
| `samples/` | 연습용 가짜 거래내역서 (PDF 비밀번호 `900101`, 같은 내용의 CSV) |
| `tests/` | 테스트 (AI 호출은 가짜로 대체) |

## 공유용 데모 페이지

서버 없이 브라우저에서 돌아가는 데모를 HTML 한 파일로 만들 수 있어요. 화면은 `static/`을 그대로 쓰고,
서버 대신 `demo/mock_api.js`가 연습용 가짜 거래로 응답해요(업로드·AI 호출은 막혀 있음).

```bash
python demo/build_demo.py
```

결과는 `demo/dist/spending-demo.html`에 생겨요. 화면을 고친 뒤 다시 실행하면 최신 화면으로 다시 만들어져요.

## 분류 정확도 재기

직접 고른 카테고리를 정답으로 삼아, AI가 몇 %를 맞히는지 잴 수 있어요(Claude를 부르므로 API 키와 소액 비용 필요).

```bash
python -m app.agent.evaluate
```

정답을 3묶음으로 나눠, 맞히는 묶음의 정답은 숨기고 나머지 묶음의 선택만 예시로 줘요.
프롬프트나 단서를 바꾼 뒤 전후로 돌려 비교하세요.

### 정답 데이터 만들기 (검증용 DB)

앱 DB와 따로 `data/eval.db`에 거래내역을 넣고, 클릭으로 정답을 매겨 채점해요.

```bash
python -m app.agent.answer_sheet export --no-ai "토스.pdf"   # 검증용 DB + 정답 매기기 화면
# data/정답_매기기.html 을 브라우저로 열어 입출금마다 정답을 고르고 정답.csv 저장
python -m app.agent.answer_sheet load 정답.csv
python -m app.agent.evaluate --db data/eval.db --engine both  # 나간 돈: 기존 API vs Console 에이전트
python -m app.agent.evaluate --db data/eval.db --target in    # 들어온 돈: 정산·용돈·알바비·환불·기타 수입
```

## AI 구성

- 기본 모델은 **Claude Haiku 5.5** (`.env`의 `CLAUDE_MODEL`로 바꿀 수 있음).
- 나간 돈: 가게 이름 단위 분류 → 애매한 거래만 앞뒤 거래·정산 단서로 하나씩 추측.
- 들어온 돈: 결제 취소·확정 정산은 규칙으로, 나머지는 보낸 사람 패턴·근처 결제 금액으로 종류를 추측.
- 어려운 거래는 Claude 콘솔에서 만든 **분류 전용 에이전트**(Managed Agents)에게 맡길 수 있어요(`app/agent/managed.py`).
  에이전트는 앱이 주는 거래 조회 도구(`app/agent/agent_tools.py`)로 필요한 만큼 더 찾아봐요.
  - `.env`에 `GUESS_ENGINE=agent`, `AGENT_VERSION=8`을 넣으면 분류 확인 거래를 에이전트 v8이 추측해요.
    에이전트가 실패하거나 빠뜨린 거래는 기존 API가 대신 추측해서 업로드는 멈추지 않아요.
  - 분류 규칙은 스킬로 따로 둬요: `.claude/skills/transaction-categorizer/SKILL.md` (콘솔에 올려 에이전트에 붙임).
  - 검증 결과: 정답 372건 기준 에이전트 v8 69%, 기존 에이전트 55%, Haiku 단독 63% — `docs/에이전트_v8_성능검증.pdf`.
- 주간 보고서는 콘솔의 **보고서 전용 에이전트**(주간 실지출 리포터)가 써요(`app/agent/report_agent.py`).
  - `.env`에 `REPORT_ENGINE=agent`, `REPORT_AGENT_VERSION=3`. 실패하면 기존 API가 대신 써요.
  - 숫자는 앱 도구(week_summary · budgets · find_transactions · last_report)가 계산하고, 에이전트는 글·표·그래프만 써요.
  - 양식은 스킬 `.claude/skills/weekly-report-writer/SKILL.md`. 보고서 속 ```` ```chart ```` JSON 블록은 화면에서 막대그래프로 그려져요.
